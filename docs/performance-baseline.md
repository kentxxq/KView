# KView 性能基线

## 记录口径

- 文档核对日期：2026-10-19。本节按当前实现更新说明；同日的应用更新测试没有重新采集性能基线。
- 以下数值均为 2026-07-17 的历史测量，不代表当前版本的实测结果。
- 环境：Windows 11 x64，系统 WebView2；debug 与 release + NSIS 安装版分别记录，不跨构建类型比较。
- 冷启动：从创建进程到 KView 主窗口可被系统识别。
- 后台唤起：托盘进程仍在时，从传入文件到窗口恢复；极速与低内存模式分别记录。
- 文件加载：前端收到打开请求到 Viewer 数据加载完成；记录在本地 `diagnostics.jsonl`，不含路径。
- 内存：同时记录 KView 主进程和其 WebView2 子进程工作集；debug WebView2 数据仅用于同环境相对比较。

## Windows 实测

采集日期：2026-07-17。以下结果用于后续相同口径的相对比较，不代表 release 安装包指标。

| 场景                       | 本轮结果 | 说明                                                                           |
| -------------------------- | -------: | ------------------------------------------------------------------------------ |
| 冷启动到原生窗口           | 4,862 ms | debug 模式，包含 Vite 开发服务器与 Rust 启动；窗口随后通过辅助功能树确认可交互 |
| 极速模式后台文件唤起       |   281 ms | 以 `--background` 静默启动并预建隐藏 WebView，传入文本文件后恢复现有窗口       |
| 低内存模式后台文件唤起     |   259 ms | 以 `--background` 静默启动且不创建 WebView，传入文本文件后重建窗口             |
| JSON 加载                  |  12.2 ms | 140 B，UTF-8 BOM + CRLF                                                        |
| PNG 加载                   |  11.9 ms | 128 × 128 应用图标                                                             |
| UTF-16 文本加载            |  10.7 ms | UTF-16 LE BOM + CRLF                                                           |
| 大日志加载                 |  99.0 ms | 22,020,108 B，初始只读加载前 2 MiB                                             |
| 极速模式空闲主进程工作集   | 34.4 MiB | WebView 保留；6 个 WebView2 子进程，总工作集约 530.9 MiB                       |
| 低内存模式空闲主进程工作集 | 35.8 MiB | WebView 销毁；0 个 WebView2 子进程，总工作集 35.8 MiB                          |
| 大日志打开后主进程工作集   | 34.5 MiB | 单实例 KView 主进程                                                            |

冷启动验收额外连续执行两次，均无需手动刷新即可显示空白页。测试中发现并修复了模板遗留 `vue-router` 导致的 `504 Outdated Optimized Dep` 调试冷启动白屏。

驻留模式验收通过本地诊断日志交叉确认：极速模式记录 `window-hidden`，低内存模式记录 `window-destroyed`；两种情况下 Rust 主进程与托盘均保持存活。模式选择在窗口销毁并重建后仍能正确恢复。

`--background` 启动也分别复验：两种模式均未出现可见主窗口；极速模式存在 WebView2 子进程，低内存模式不存在 WebView2 子进程。随后传入文件时均只保留一个 KView 主实例，并正确显示文本 Viewer。

后续比较必须使用相同构建类型、同一组样例文件和相同计时口径。

## Windows 安装版复验

采集日期：2026-07-17。构建为 Windows 11 x64 release + NSIS 安装版，样例统一使用仓库 `README.md`。端到端耗时从第二实例传入文件开始，到前端完成 Viewer 加载并写入性能诊断为止；每组 6 次，去掉首轮后取中位数。

| 场景                    | 中位数 | 最慢热样本 | 关闭窗口后的 KView 进程树                                              |
| ----------------------- | -----: | ---------: | ---------------------------------------------------------------------- |
| 极速模式打开 Markdown   | 149 ms |     174 ms | 1 个 KView + 1 组 WebView2（6 个系统子进程），私有内存合计约 240.8 MiB |
| 低内存模式打开 Markdown | 755 ms |     785 ms | 仅 1 个 KView，0 个 WebView2 子进程，私有内存约 9.3 MiB                |

本轮历史样本中，低内存模式的打开耗时约为极速模式的 5 倍。当时关闭窗口前会先清空当前文档状态并卸载 Viewer 组件；极速模式仅保留唯一的隐藏 WebView 壳，低内存模式销毁该 WebView。该测量策略不等于当前默认关闭行为。

Windows 任务管理器中的多个 `msedgewebview2.exe` 不代表创建了多个 KView 窗口。一个 WebView2 进程组会按职责拆分浏览器、渲染器、GPU、网络/存储服务和崩溃处理进程；本轮进程树中只有 1 个 renderer，且代码中只有 `main` 一个 WebView 窗口。

## 当前关闭行为与待补基线

以下行为按 2026-10-19 的代码核对，尚未进行本轮性能实测：

- 极速模式默认隐藏窗口并保留全部标签、Viewer 和未保存编辑内容，再次打开时继续使用；内存占用取决于保留的文件和 Viewer，不能套用历史空壳数据。
- 极速模式可选择关闭全部标签；关闭前处理未保存修改，释放文档及 Viewer 资源后隐藏窗口。后续测量应单独记录该设置。
- 低内存模式关闭全部标签并销毁 WebView，保留 Rust 主进程和托盘；再次打开时重建窗口。

后续实测需分别覆盖上述三种关闭策略，记录构建版本、WebView2 版本、固定样例及大小，并区分主进程与 WebView2 子进程的工作集或私有内存。历史两种内存口径不能直接比较。

待补数据：当前版本的冷启动、三种关闭策略下的再次打开耗时及关闭后内存，以及保留文本编辑器、PDF、音频和视频标签时的资源占用。本次不填入推测数值。

## 目标与告警线

- 冷启动、后台唤起和典型文件加载不出现秒级无响应。
- 22 MiB 日志初始只读加载前 2 MiB，后续使用有界窗口按需读取，不将完整文件载入编辑器。
- 本地诊断日志单文件上限 256 KiB，最多保留当前文件和一个轮转文件。
