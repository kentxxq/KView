# Git 提交与推送流程

当用户手动触发，禁止自动执行！用于将代码变更提交并推送到远端仓库。

## 1. 梳理变更内容

在提交之前，需要确认本次修改的具体内容，以便编写准确的提交信息。

1. **查看状态**：
   - 运行 `git status` 查看已修改的文件。
   - 特别注意根据不同的项目类型检查是否有版本号变更。例如前端项目必须检查 `package.json` 是否有版本号 (`"version"`) 的变更。

2. **总结变更**：
   - 识别本次提交的核心目的（是新功能、修复、优化还是清理）。
   - 如果检测到版本号变更，提取新的版本号（如 `0.0.6`）。

## 2. 准备提交信息

使用 Emoji 增强提交信息的可读性。

- ✨ `feat`: 新功能
- 🐛 `fix`: 修复问题
- 🛠️ `refactor`: 代码重构/优化
- 📝 `docs`: 文档更新
- 💄 `style`: 样式调整
- 🗑️ `chore`: 琐事、清理或构建工具变更

**格式建议**：
提交信息永远使用中文描述，在必要的地方添加英文关键词。单词改动内容较多的时候可以有多行的提交信息，第一行是简短描述，后面可以有更详细的说明。

下面是第一行提交信息的格式建议：

- 普通提交：`:emoji: <类型>: <简短描述>`
- **带版本的提交**：`v<版本号> :emoji: <类型>: <简短描述>`

下面是一个完整提交信息的示例
```md
v0.0.6 ✨ feat: 添加自动化发布功能

- 通过检查 `package.json` 中的版本号变更，自动化生成提交信息。
- 版本号变更时自动打标签并推送标签到远端。
- 通过使用 Emoji 增强提交信息的可读性。
```


## 3. 执行提交、打标签与推送

1. **暂存文件 (Git Add)**：
   - 运行 `git add .` 暂存所有变更。

2. **提交变更 (Git Commit)**：
   - 运行 `git commit -m ":emoji: <message>"`。
   - 确保如果版本号有变，提交信息以 `vX.Y.Z` 开头。

3. **打标签 (Git Tag - 仅在版本号变更时执行)**：
   - 如果 `package.json` 中的版本号发生了变化，为本次提交打上对应的版本标签。
   - 运行 `git tag v<版本号>` (例如: `git tag v0.0.6`)。

4. **推送至远端 (Git Push)**：
   - 检查当前分支：`git branch --show-current`。
   - 运行 `git push origin <branch_name>`。
   - **推送标签**：如果打了标签，运行 `git push origin --tags`。
