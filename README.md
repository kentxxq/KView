# KView

KView 是一款面向开发者和高级用户的现代化跨平台文件查看与轻量处理工具。它结合 QuickLook 的打开速度、VS Code 对开发文件的理解能力和 macOS Preview 的简洁体验，让用户无需启动大型应用就能快速打开、理解和处理本地文件。

> 快速打开文件、快速理解内容，而不是为了查看文件而启动一个庞大的应用。

## 产品定位

KView 主要服务于经常查看日志、配置文件和结构化数据的开发者，以及只需要快速浏览图片、文档、表格、压缩包、音频和视频的高级用户。

项目坚持以下边界：

- 无广告、无强制登录、无复杂配置，文件内容仅在本机处理。
- 文本和代码可编辑；图片、PDF、Office、电子书、安装包、压缩包、音频和视频只读。
- 优先优化打开后的体验，不追求替代 Microsoft Office、WPS、Adobe Acrobat 或专业媒体编辑器。
- 暂不提供 PDF 标注、OCR、Office 高保真编辑或内置云账户体系。

## 已实现功能

### 文件打开与工作区

- 支持系统文件关联和“打开方式”、应用内文件选择、窗口拖拽以及运行中再次双击文件。
- Windows 资源管理器或桌面中仅选中一个文件时，可按 `Space` 聚焦 KView 并快速打开；使用四个方向键可按同目录文件名自然排序循环预览，按 `Esc` 或再次按空格关闭窗口。输入框、弹窗及动态照片保留自身的空格操作；切换标签后解除空格预览关联，原标签继续加载。
- 支持从首页或标题栏打开公开的 HTTP/HTTPS 图片、PDF 和视频 URL；首页还可直接粘贴 URL 或剪贴板图片，远程与剪贴板内容仅在当前会话中保留。
- 单实例运行；新的打开请求会交给已有进程处理。
- 支持多标签打开、切换和关闭，并保持每个标签的 Viewer 状态。
- 自动恢复上次标签会话和活动文件，自动清理已经失效的路径。
- 提供最近打开与收藏；仅保存本地路径和时间，不复制文件内容。
- 提供应用快捷键、原生菜单和标签页右键菜单；可关闭当前标签、右侧标签、其他标签或全部标签。
- 关闭标签页或清空工作区时，仅针对本次将被关闭且存在未保存修改的标签页提供保存、放弃或取消保护。
- 无文件启动时显示空白页，可拖拽或选择文件；损坏、无权限和不支持的文件使用统一错误状态。
- 标题栏提供回到首页入口；返回前会处理所有未保存修改并关闭所有标签。
- 无法识别的二进制文件或不支持编码的文本可切换为十六进制 Viewer。

### Viewer 与格式

所有 Viewer 均通过内部注册表按需懒加载，Monaco、PDF.js 和 Office 解析依赖不会进入空白页首屏加载链路。

### 文本读取与保存

- 支持 UTF-8、UTF-8 BOM、UTF-16 LE BOM 和 UTF-16 BE BOM。
- 保存时保留原编码、BOM 和 LF/CRLF/CR 换行符。
- 文本默认超过 2 MiB 时进入分页只读模式，后台建立索引后按需读取可见行；完整编辑的大小阈值可在设置中调整。
- 保存前比较源文件修改时间，发现外部修改时阻止静默覆盖。
- 使用同目录临时文件和原子替换保存，失败时不破坏原文件。
- JSON/YAML 格式化仅修改编辑缓冲区，必须显式保存才写入源文件。

### 桌面生命周期与设置

KView 使用一个 Tauri/Rust 进程负责单实例协调、托盘、文件打开事件、文件读写和窗口生命周期，不引入独立后台服务。

- 默认开机静默启动到托盘，`--background` 启动不会显示主窗口。
- 打开文件时会创建、恢复或聚焦唯一窗口。
- 托盘提供“打开 KView”“开机启动”和“退出”；只有明确退出才结束后台进程。
- 提供跟随系统、浅色和深色主题。
- Windows 安装、覆盖升级和启动时不自动注册文件格式。设置页的“文件关联”提供“注册文件关联”“取消注册”和“前往系统设置”按钮，可按需添加或清理 KView 的打开方式；默认应用由用户在 Windows 中选择。
- 提供两种持久化驻留模式：
  - **极速模式（默认）**：关闭窗口时隐藏窗口并保留 WebView，默认同时保留全部标签页和未保存编辑状态，再次打开可继续使用；也可改为关闭全部标签页。
  - **低内存模式**：关闭标签页并销毁 WebView，仅保留 Rust 进程和托盘，再次打开时按需重建窗口。
- Esc、标题栏关闭按钮和系统窗口关闭遵循统一的关闭行为设置；保留标签页仅适用于极速模式。

## 核心架构

```text
文件关联 / 拖拽 / 文件选择器 / 第二实例
                    ↓
             归一化打开请求
                    ↓
     共享能力清单判定平台与文件类型
                    ↓
       Rust 文档命令读取类型化内容
                    ↓
       Pinia 工作区提交加载事务
                    ↓
          Viewer 注册表按需懒加载
```

### 核心模型

- `OpenedFile`：归一化后的路径、文件名、扩展名、大小、修改时间、类型、编码、换行符和只读状态。
- `ViewerKind`：空白、图片、动态照片、文本、Markdown、JSON、YAML、PDF、DOCX、XLSX、电子书、安装包、压缩包、音频、视频、十六进制或不支持。
- `FormatCapability`：格式、扩展名、支持平台、文件关联和 Viewer 类型的唯一声明来源。
- `ViewerDefinition`：Viewer 类型与懒加载入口，不再重复维护格式支持范围。
- `DocumentState`：标签内文件、加载/错误状态、类型化内容、脏状态和源文件修改时间。
- `DocumentContent`：文本、原始二进制、Data URL、结构化结果或会话内容的判别联合。

### 职责边界

Rust Core 负责路径归一化与安全校验、元数据和类型检测、文本编码探测、完整或分块读取、原始二进制 IPC、原子保存、外部修改冲突检测，以及单实例、托盘、自启动和窗口生命周期。

Vue 前端使用 Pinia 保存标签、设置和文件库状态；文档加载器以原子事务提交结果，并统一释放加载阶段创建的 Object URL 与 Rust 会话；Viewer 卸载时释放其媒体 URL、Worker 和解析任务。前端不具备任意文件系统访问权限，所有文件操作均经过类型化桌面 API 调用范围明确的 Rust 命令。

文件类型首先按扩展名初筛，再使用文件头或内容特征校验；文本还会执行编码探测和二进制排除。检测结果冲突时选择更安全、保守的 Viewer。

## 安全与隐私

- Tauri capability 按最小权限配置，不向前端开放任意路径读写。
- CSP 只允许应用所需的本地资源、Worker、Blob 等来源。
- SVG、Markdown 和 DOCX 产生的 HTML 均按不可信内容处理并清理。
- 外部链接只有经过用户明确操作后才交给系统打开。
- URL 打开仅允许 HTTP/HTTPS，不接受 URL 内嵌账号密码、Cookie 或自定义请求头；响应会经过格式识别和大小限制后才交给 Viewer。
- Office 宏、文档脚本和潜在不可信链接不会执行。
- 本地诊断日志仅记录时间、错误类别、错误代码和耗时，不包含文件路径或内容。
- 诊断日志单文件上限为 256 KiB，最多保留当前文件和一个轮转文件。

## 平台支持与差异

- **Windows 10/11 x64**：使用系统 WebView2；默认提供 NSIS 当前用户安装包，无需管理员权限。
- **macOS 12 及以上**：使用系统 WKWebView；应用包、图标、文件关联和 LaunchAgent 开机启动已配置。
- KView 不内置浏览器运行时，因此最终渲染和媒体解码能力会随系统 WebView 版本变化。
- Windows 文件打开通过单实例参数转发；macOS 还会处理系统 `Opened` 文件事件。
- 两个平台的托盘排列和系统图标样式可能不同，但功能保持一致。
- Windows 原有核心流程及两种驻留模式已经完成人工验收；本次手动文件关联调整仍需复验安装、覆盖升级、注册、取消注册和卸载。macOS 发布前仍需复验安装、升级、卸载和文件关联。
- Windows 覆盖安装保留已有文件关联注册和旧版备份，只更新已有注册的程序路径；取消注册或卸载会清理 KView 文件类及备份，并在扩展名仍指向 KView 时恢复旧版备份，不影响其他应用的关联。Windows 中已选定的默认应用需要用户在系统设置中更换，取消注册不保证恢复之前的默认应用。
- 极速模式的一个 WebView2 实例会按浏览器、渲染器、GPU、utility、crashpad 等职责产生多个系统子进程，这不代表存在多个 KView 窗口；低内存模式关闭窗口后不保留 KView 所属的 WebView2 子进程。

## 已知限制

- 文本仅支持 UTF-8、UTF-8 BOM 和带 BOM 的 UTF-16 LE/BE；其他本地编码会显示错误，并可按二进制方式查看。
- 超过设置阈值（默认 2 MiB）的文本使用分页只读浏览，不提供编辑、格式化、Markdown 预览或 JSON/YAML 树形视图；单张图片安全上限为 100 MiB，LIVP 容器及其解压后媒体总量安全上限为 300 MiB。
- 远程图片安全上限为 100 MiB，远程 PDF 和视频安全上限为 200 MiB；不支持 HTML 网页、HLS/DASH 流媒体清单和需要登录鉴权的资源。
- SVG 会移除脚本、事件属性和 `foreignObject`，复杂 SVG 的外观可能发生变化。
- DOC/DOCX 复杂版式可能与原文件不同；不支持宏和 Office 级排版保真。
- XLS/XLSX 不承诺宏、图表、公式重算和复杂样式保真。
- EPUB/MOBI 仅提供基础安全排版，不执行书内脚本、不加载外部资源，不支持 DRM、固定版式还原、AZW/AZW3、书签或阅读进度。
- MOV 仅在当前系统 WebView 实际支持对应编码时可播放。
- 音频播放依赖当前系统 WebView 的容器和编码支持；已识别的音频格式仍可能无法解码。当前只支持本地音频，不支持从 URL 打开音频。
- 压缩包最多展示前 5,000 个条目，当前仅供浏览，不提供解压和修改。
- 图片、动态照片、PDF、Office、电子书、安装包、压缩包、音频和视频均不会修改源文件。
- HEIC/HEIF 静态部分在 Windows 上优先使用系统 WIC/HEIF 解码器，缺少系统组件或其他平台时回退应用内置解码器；解码后的无压缩预览通过二进制 IPC 传输并按路径和修改时间缓存，不再执行 PNG 压缩或 Base64 转换。Live Photo 的 MOV/MP4 动态部分仍依赖当前系统 WebView 支持对应的视频编码，不支持时保留静态封面并显示兼容提示。

## 自动构建

普通分支推送及 Actions 页面手动运行 `Tauri Build` 会构建 Windows x64、macOS Apple Silicon（arm64）和 Intel（x64）安装包，构建物保存为 Actions artifacts，不发布正式更新。

正式版本从 [最新 Release](https://github.com/kentxxq/KView/releases/latest) 下载：

- Windows：`KView-windows-x64.exe`。
- macOS：`KView-macos-arm64.dmg` 或 `KView-macos-x64.dmg`。
- Windows 使用当前用户安装模式，覆盖升级保留设置及已有文件关联。
- 当前没有配置系统代码签名证书或 macOS 公证，macOS 首次打开可能需要在系统设置中允许运行；更新包签名不替代系统代码签名。

工作流使用 [Vite+ 官方 CI 安装工具](https://viteplus.dev/guide/ci) 安装环境，沿用 pnpm 和 Cargo 锁文件。

### 应用内更新

- 正式版进程启动后自动检查一次，此后每 6 小时检查；开发模式不自动检查。
- 有新版时在可见窗口内提示，托盘运行时不主动弹出窗口；同一版本在本次进程中只提醒一次。
- 在“设置 → 关于”手动检查、查看更新说明、下载安装或失败重试。后台检查失败不会弹出错误。
- 用户点击更新后才下载；显示已下载大小及可用的总进度。关闭窗口不会中止 Rust 进程中的下载，低内存模式重建窗口后可继续查看状态。
- 下载并校验签名后，安装前处理全部标签的未保存修改；取消或保存失败会保留当前工作区及已下载更新，稍后可点击“安装并重启”。进入安装阶段后暂停编辑及新文件打开。
- 更新成功后自动重启，恢复可恢复的本地标签路径、最近打开、收藏和设置；剪贴板及远程文件会话不会恢复。
- 首个具备更新能力的正式版本为 `1.0.0`。更早版本需要手动安装一次，之后才能应用内更新。
- 使用 GitHub Releases 的 HTTPS 更新清单和 Tauri 签名校验，客户端不携带 GitHub Token；仅支持稳定版，不支持降级。

### 配置更新签名

首次发布前，在 GitHub 仓库的 **Settings → Secrets and variables → Actions** 配置：

| Secret | 内容 |
| --- | --- |
| `TAURI_SIGNING_PRIVATE_KEY` | 与应用内公钥配对的私钥文件完整内容，不是本机文件路径 |
| `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` | 私钥密码；无密码时不设置即可 |

本次接入已在本机用户目录 `%USERPROFILE%\.tauri\KView\updater.key` 生成无密码私钥，其 `.pub` 公钥已写入 Tauri 配置。私钥没有进入项目目录，也没有输出到日志。请将私钥保存到上述 Secret 并在仓库外备份；该本机文件只存在于接入功能的开发机器。

其他维护者应沿用配对密钥。需要自行生成新密钥时，可使用以下命令，将 `REPLACE_ME` 替换为仓库外的永久保存路径，并同步配置对应公钥；已发行版本无法验证另一把私钥签署的更新。

```shell
vpr tauri signer generate -w REPLACE_ME
```

普通分支构建不读取发布私钥；正式发布缺少私钥时会失败。只有 `tauri.release.conf.json` 开启更新产物生成，本地普通构建无需配置私钥。

### 发布正式版本

Actions 仅在推送 `v*` 标签或手动运行时触发，普通分支推送不触发工作流。

1. 同步修改 `package.json`、`src-tauri/Cargo.toml`、`src-tauri/tauri.conf.json` 的版本，并更新 Cargo 锁文件中的根包版本及 `CHANGLOG.md` 中的对应版本说明。
2. 将经过验证的提交合入 `main`，由维护者创建并推送对应 `vX.Y.Z` 标签。首次正式发布为 `v1.0.0`；新标签必须高于其他正式版，已公开版本的附件不能覆盖。
3. Actions 校验版本和提交来源，然后构建三个平台。Windows 生成安装包和签名；macOS 同时生成 DMG、应用更新压缩包及签名。
4. 全部成功后，发布任务创建或继续版本草稿，上传所有安装包、更新包、签名和包含三个平台的 `latest.json`，校验文件数量、大小和 SHA-256 摘要后公开对应的 `vX.Y.Z` Release。
5. 将 `latest` 标签移动到同一提交，将新版本 Release 标题设置为 `latest (vX.Y.Z)` 并标记为 GitHub 最新 Release；上一版本标题恢复为其 `vX.Y.Z` 版本号。每个正式版本只有一份 Release，所有历史版本标签、附件和说明持续保留。

更新清单中的下载链接绑定对应版本标签，固定的“最新 Release”入口直接访问当前版本的同一份附件，不再复制第二份安装包。任何平台构建或版本附件上传失败时，不切换正式更新渠道。可以重跑失败的发布任务，未公开草稿允许重试，已公开版本仅校验内容一致性，不覆盖附件。手动运行标签只构建普通安装包，不发布。

固定下载入口使用 [最新 Release](https://github.com/kentxxq/KView/releases/latest)，应用内更新继续使用 `/releases/latest/download/latest.json`，无需重新安装已发布的 `1.0.0`。`latest` Git 标签和最新版本标签指向同一提交；不再单独发布 `latest` 标签的重复 Release，原 `/releases/tag/latest` 或 `/releases/download/latest/...` 链接应改用固定入口。GitHub 没有强制置顶接口，因此采用最新版本标题显示 `latest (vX.Y.Z)` 的方式，不再让重复条目参与排序。

发布仅使用 `Tauri Build` 工作流，正式发布流程会自动整理发布名称并同步 `latest`。迁移时先校验重复 `latest` 的每个附件都已完整保存在某个正式版本中，再清理重复 Release；不删除 Git 标签，不重建安装包，也不覆盖版本附件。正式发布前需分别人工验收 Windows x64、macOS arm64 和 x64 的安装升级、签名失败拦截、未保存修改保护与设置及本地会话恢复。
